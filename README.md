# Serico 个人主页

这是 Serico 的中英双语个人主页。读者主要是做外贸、做企业、想用 AI 提效、自己不写代码的老板：看完应当带走一套完整的思路（哪些活值得交给机器、怎么挑第一步、人留在哪、哪些事不交给 AI），并记住 Serico 这个名字。页面只讲思路，不讲做法：工具名、模型名、提示词、系统怎么搭、怎么维护，一个字都不写；站主现在没有对外的落地项目，也不能写得像在接单。仓库里已有可运行的 Astro 静态站，可以直接在现有页面上调整设计。[English](https://serico.ai/) · [中文首页](https://serico.ai/zh/) · [源码仓库](https://github.com/bestduijin/bestduijin.github.io)

## 视觉与阅读体验

设计从名字里的「丝」取材，整页是同一片夜（2026-11-25 起固定深色，不再跟随系统的浅色）。颜色都取自首屏的画，定义在 [global.css](src/styles/global.css)：底色夜空 `#070b1a`（首屏底边是 `#070c20`，下面从这个颜色渐到底色，接缝看不出来），大字暖白 `#f3f0ea`，正文雾灰 `#cdd0e0`，小字 `#8b91ad`；丝带的粉 `#ea91a8` → 金 `#e8c488` → 青 `#74d4c9` 只用在四处：丝线、四步序号的悬停、分工表里当前行（和悬停那一行）的序号和左边短线、最后的 serico。新加的段落只靠字号、细线和留白，没有配图、色块和卡片；编号只有两处：四步（01–04）和五道工序（01–05）。

字体（2026-11-26 站主看过对比图后定）：三种西文字体，各管一摊。**Bodoni Moda 斜体只给 Serico 这个名字**：首屏字标、页脚小字标、「名字的来历」里的 Seres / sericus / serico。**DM Serif Display**（只有 400 一个字重，层次靠字号）管大字：首屏两行、三个数字、各段大标题、四步的步骤名、自述（英文自述用它的斜体，比下面的四个词轻）；序号 01–05 用它的斜体。**Hanken Grotesk** 管首屏以下的正文和所有小字：表头、图注、按钮、语言链接和提示、数字旁的小标签、页脚；情形和三件事的小标题、分工表的工序名用它的 600（中文页这几处的汉字仍是宋体常规）。三级是：大标题 DM Serif Display → 小标题 Hanken 600 → 正文 Hanken 400。中文和拉丁字之间的空格（如「交给 AI」）原样保留，分词时空格单独留在词与词之间，不会被吃掉。中文大字仍用设备上的宋体、中文正文仍用设备上的黑体（苹方等），中文行里夹的 Serico、AI、数字跟着上面的规则走（DM Serif Display 的 `size-adjust` 是 98%，夹在宋体里和汉字一样大）。英文字号：正文 18–18.75px（Hanken 字身高，x 高 0.49em，这样读起来和以前 Jost 的 19–20px 一样大）、行高 1.68，行宽约 60–70 个字符；分工表格子 17px；表头、「仅作演示」、词源下面的小字 14px；段落大标题 31–54px（1440 宽约 54px）；四步的步骤名 21–26px；情形、三件事的小标题和工序名 18–21px（Hanken 600）；英文自述 22–36px 斜体、行高 1.45。中文正文、表格、附注的字号不变（中文 17–18px，附注 15px）。三种字体都通过 Fontsource 打包、随站点加载（只加载拉丁子集，按 `unicode-range` 用到才下载，不连外面的字体服务），许可都是 SIL Open Font License 1.1，版本在 `package.json` 里写死。中文大字（大标题、各段的小标题）先按标点断行，一句放不下再在词与词之间换行（构建时用 `Intl.Segmenter` 分词），不会把「经验」「东西」拆开；短段落用 `text-wrap: balance`。正文每段最后几个词连在一起不拆（中文至少 4 个字、英文 2 个词，`Page.astro` 的 `para`），不会有一两个字或一个词单独掉一行。

**丝线**是首屏以下唯一的滚动动效（[src/scripts/silk.ts](src/scripts/silk.ts)）：一根细线从首屏底缘渐显出来，几道从容的大弧往下走——沿右边页边落下，在「现在在做」和名字那一段之间横着摆过整个页面（从丝带画上方经过）；「三件事」的大标题左边要么不走，要么只走页边外侧三分之一（1280 宽及以上，找路时离这行字留 58px，`silk.ts` 的 `PAD.wide`；2026-11-26 起，1440 宽也因此改成这条走法，原来是在演示视频和「三件事」之间横摆、贴着这行大标题左边落下）；然后从名字左边落下，最后一道整圆弧（半径最大 130px，`silk.ts` 的 `LANDING`；2026-11-27 前是 160px，换字体以后英文宽屏最后一段落在离屏幕边 40px 处，横摆过来拐不过这个弯）顺势落进四个词上方的线，停在 serico（四个词竖排时，它从上面直接落到第一个词，顺着竖线往下）。走法不是写死的：打开页面时等字体就绪（`document.fonts.ready`，最多等 1.5 秒，字体一直不来也照样画）找一次，之后只有窗口宽度变了（或晚到的字体把页面挪动了）才重新找；只改高度（手机工具栏伸缩）不重新找路，只重算画的进度。找路之前只有四个词之间那条静态细线（和没有脚本时一样），线一出现就在最终位置，不会先有后无或跳一下。脚本按页面上文字、视频、按钮的真实位置，在一张粗网格上找一条「弯得少、尽量走在空处」的路线；线本身只取这条路线上的少数几个点（1440 宽约 10 个，相隔约 380px），用向心 Catmull-Rom 拟合成一整条平滑曲线。曲线离东西太近时，整点挪开或补点后整条重新拟合；拐得太急（曲率半径不到 80px）时，去掉或挪动附近的点再整条重新拟合，从不逐点修。净空：离大标题和自述至少 40px（768 宽时页边只有 46px，放宽到 28px），离其他文字 20px、按钮 24px、视频、四步列表和分工表 16px，离屏幕边 12–20px；分栏的段落（情形、三件事、现在在做）整段不穿（不从栏缝里走）。为了让线能从容地横摆过去，「三件事」和名字那一段前面的段间距加大到约 1.5 倍（13–15rem）。找路加拟合一次约 60–190ms（比这台机器慢 4 倍的笔记本上约 0.8 秒）：先用较稀的点，弯不到 80px 就换几种疏密再试，满足了就停；找到哪一条只看页面，不看机器快慢，慢机器上也是同一条线。只有一个保险：整次超过 2 秒（`silk.ts` 的 `LIMIT`）就用已经找到的最好那条。弯的急缓连同落进圆弧的那一下一起量。窗口拖动时等停下来才重算。字体迟到时（1.5 秒兜底已经画了一次），字体到了只在四个词的位置真的变了时才再找一次。页边窄到走不出来时（手机），只画四个词旁边那条竖线；768 宽中英文、820 宽中文是完整的线；820 宽英文（演示段大标题几乎占满一行，两边留不出净空）和 834、900、960、1112 宽找不到路，也只画那条线。`.night` 上的 `data-silk` 写着这次是完整的还是只画了线、用了几个点、最急的弯多大、花了多少毫秒，`data-silk-runs` 是打开以来找了几次路。画的进度跟着屏幕走：线画到哪，大致就在屏幕从上往下 75% 的位置；四个词上方那条线进入这个位置就开始画，再滚大约三分之一屏画完。开了「减少动态效果」时整根直接显示；没有脚本时四个词之间有一条静态细线（CSS），内容照样都在。除了丝线、首屏的光、演示视频和跟着视频亮起的那一行，页面上别的东西都不动。

两幅画在 `public/art/`：`band.webp`（「名字」背后的丝带，手机用 `band_tall.webp`，现在还是从首屏的画裁出来顶着的）、`ending.webp`（页尾的沙丘远城，手机用 `ending_tall.webp`，2026-11-26 换成了专门画的新图；原图和原来的首屏裁图备份不在本仓库里）。换画只换这些文件，页面只认文件名，四边用遮罩融进底色；换画以后要重新确认压在画上的字对比度够（≥ 4.5:1）。

首屏插画在 `public/hero/`：`hero_wide.webp`（宽屏）、`hero_tall.webp`（宽高比小于 3:4 的手机），这两张图的草稿和生成脚本不在本仓库里。上面的光是 [src/scripts/sky.ts](src/scripts/sky.ts) 用 canvas 画的，丝带、驼队、城市的位置是照两张画描的坐标，**换了画就要重描**。

### 首屏的驼队动画

首屏画上沙脊那一队骆驼会走（[src/scripts/caravan.ts](src/scripts/caravan.ts)，和天上的光画在同一块 canvas、同一个动画循环里）：沿着画里那条金色的路，来回拐着走到右边远处的城，越远越小、越淡，最后只剩几点灯火融进城里；第一队快走到第一个回头弯时，左边沙脊背后先亮起一片暖光、沙脊勾出一道金边、几颗灯火往上飘，接着一支更气派的队伍（13 头，三四头一簇，簇和簇之间留空）翻上沙脊，领头的驮货上飘起一条长长的丝带（玫瑰金，尾梢带青，和天上的丝带同一种颜色）；每支驼队踩过的路和沙地都会亮起来，身后拖着一条慢慢暗下去的光带；之后普通的、气派的轮流接上，一直循环。

走得慢而稳，是有意的（驮着货一路走到，不是赶路）：近处每秒走 12 个图片像素（画上的骆驼高 20 像素、约合 2.1 米，折下来约每秒 1.3 米，是驮货骆驼平常的步速），四条腿各落一次地约 1.3 秒。第一队约 84 秒到城；带丝带的第二队（气派一队）在开页后第 27 秒出发：大屏上约 24 秒时沙脊背后亮起预告的光，约 30–31 秒头一头翻上沙脊，之后每 55 秒来一队（约 86 秒、141 秒……普通的、气派的轮流）。窗口小、字挡住路的起点时，新队要走过字后面那一段才露头，所以晚几秒（1440×900 中文约 33 秒，1366×768 中文约 39 秒）；不让它提早出发来补，是因为各队之间隔多远在每种窗口都得一样，不然丝带会压到前一队的队尾。路上同时最多三队，而且只在交接的一小会儿：最老的一队正在城那头化成灯火，最新的一队刚翻上沙脊，中间只有一队。想让第二队早点或晚点出来，改 `caravan.ts` 的 `SECOND_AT`（开页后第几秒出发，约 3 秒后翻上沙脊；再早 3 秒，它的丝带就会压在前一队的队尾上；现在这个数，丝带尾梢在第 74–76 秒擦过前一队最后一头的边、第 85–86 秒从远处一头很小的骆驼前面飘过，要一点不碰得改成 33，头一头约 36 秒才翻上来）；想改之后各队的间隔，改 `NEXT_AT`（上一队走完全程的几成时下一队出发）；想整体快一点或慢一点，改 `SPEED`（步子会跟着变，脚不会打滑）。

- **怎么做的**：画上原来的驼队不动，动画开始的头 0.8 秒，在原位置盖一块「没有骆驼的沙脊」补丁（同一块补丁也抹掉路上那串很小的静止骆驼；路上原有的小灯点留着），换成程序画的骆驼：骆驼的身子是从画上抠下来的那六头的剪影（放大三倍存，轮廓抹顺，六头的深浅拉齐成同一种深红褐），腿是程序画的。路线、补丁、前面挡住路的那一小块沙丘，都按图片像素存，页面按图片实际铺放的位置换算（和 `sky.ts` 一样是 `object-fit: cover`）。首屏插画没加载完之前驼队不出场（不然补丁和骆驼会先出现在一片空底色上）。
- **腿和步子**：骆驼是顺拐走（同侧的前后腿一起迈，前脚比后脚晚落地十分之一步），每只脚三分之二的时间踩在地上，抬脚很低。腿从身子里面高处摆（那一截被身子挡着），所以肚子以下只是微微前后倾；撑地的时候是直的，往前迈的时候才在膝盖（前腿）和飞节（后腿）处弯一下。脚落地以后钉在沙上不动，身子从它上面走过去：步幅是按速度和步频算出来的（`REACH`），所以不打滑。腿是上粗下细的一条、带一个扁扁的脚掌，远侧的两条腿细一点、浅一点、落脚点高半个像素。每头骆驼各走各的步子（小一点的步子快一点），整队不齐步。身子随步子有很小的起伏（0.3 像素）。腿根的位置（`bodies.json` 的 `hip`、`shoulder`）是对着原画一头一头量的。
- **踩过的地方有光**（2026-11-26 加，寓意「走到哪，亮到哪」）：驼队踩过的金路和紧挨着路的沙地会亮起来，颜色是深一点的琥珀金。最显眼的是跟着队伍走的那一片光（不放大也要一眼看得出，要的就是「一走一过的光」）：队伍脚下的路本身亮成一条琥珀金的光带，路下面的沙坡上铺开一小片淡一些的光；队伍走过去以后，两三个身位之内凉下来，只剩贴着路的一条淡淡的暗金，再慢慢暗回原样（越早踩过的越暗，没有一段一段的台阶）。两队都有，朴素的一队也一样。过回头弯时弯两边的路都亮（都踩过），但光带贴着路、压得很扁，两臂之间的沙坡是暗的。新一队翻过沙脊之前，还没踩过的路不亮；到城那头，光带跟着驼队一起淡成灯火。它不是往画上盖一层颜色，而是把那块沙地本身提亮：程序在素材加载后、浏览器空闲时（最晚 2 秒；不放在动画帧里算，免得拖住开场那几帧）取一次画上路两边的沙地（连同补丁），驼队等它算好才出场（第一队的光从出场那一刻就在）；只在驼队真要走、动画在跑的时候才取（开了「减少动态效果」、被字挡住不走的时候不取；之后点了播放或窗口变了再补取），而且只从正在显示的那张画取（同一个 `<img>` 在宽图和竖图之间换了就作废重取），算好「被灯照到」时每个像素加多少暖金（暗处多提一点，加上去的颜色整体按比例收住，亮度不超过 `CAP`、任何一个颜色通道都不溢出，所以只会变成更亮的金、不会发白），存成「这块沙地完全被照亮的样子」；每帧按光带的形状把它盖在画上，光有几成强就盖几成，亮起来的地方仍是画上原有的沙纹。（不能直接「往画上加亮」：canvas 盖在画上面，没画东西的地方是空的，往空的地方画颜色只会把底下的画盖住，不会和它相加——以前这样做，亮的金路反而被盖成一条发黑的带子，补丁的边也会在光里显出一道直线。）光带是沿路排的一串柔和的扁椭圆（按远近压扁，越远越窄越淡，越往后越窄），先画在路前面那块沙丘（`occ_*.webp`）后面，路在沙脊背后的那一段不亮；那块沙丘靠右的一头是在同一面沙坡上切出来的直线、不是画上真有的边，所以这一头照着旁边沙坡的样子也亮起来（同一条光带盖在沙丘自己的像素上），越往左、路越沉到沙脊后面就越暗（`route.json` 里这块沙丘的 `lit`：从哪起亮、到哪全亮），切口上没有一边亮一边暗的线；两队的光带交叠处最多和一条一样亮；靠近字时淡掉，和别的光一样不进字框。朴素的一队光带窄一些，最后一头走过以后约 24 秒暗完；气派的一队宽一些，约 40 秒暗完（`caravan.ts` 的 `BEAM`：宽度 `r`、亮度 `gain`、暗完的秒数 `fade`；`FLAT` 是压扁的比例，`TINT` 是光的颜色，蓝少一点：夜里的沙是紫的，光里蓝一多，照亮的沙坡就发粉）。跟着队伍走的那片光由两个数管：`HOT` 是路本身亮成琥珀金的程度（`by` 浓淡、`r` 路两边各几个像素；画上的金路已经接近它自己颜色的最亮，光带几乎加不上去，所以把路和两边几个像素往灯笼的金色 `HOT_GOLD` 上靠，最亮也只到这个金色、不会发白）；`POOL` 是沙坡上那一小片（`strength` 浓淡、`tall` 高矮、`lasts` 队尾过后几秒收掉；沙坡上故意比路上淡，照足了是一整块发白的板）。想整体淡一档：`HOT` 改成 `{ by: 0.8, r: 5.5 }`、`POOL.strength` 改成 0.45。每头骆驼脚下另有一小片灯笼照在地上的光，画在骆驼下面，腿是压在光上的深色剪影。不走的时候没有光，就是原画。
- **驼队的光一律是「盖上去」的，不是「加上去」的**：灯笼、脚下的光、沙脊背后的预告光、扬起的沙、丝带，都按各自的透明度盖在画上。canvas 上有补丁、骆驼的地方是实的，别处是空的；用相加的办法，同一片光在实的地方会比在空的地方亮，补丁的边就显成一条硬线，叠在一起的光还会烧成白色。盖上去，光到哪里都一样，最亮也只是它自己的颜色（灯笼是橙色带一点暖金的心）。灯笼都挂在脖子上方、货包顶上一点；画上有两头的灯是低的（一盏在两头骆驼之间、一盏在领头骆驼脸前），第一队从画上的位置起步、走起来再提到和别的一样高（`bodies.json` 的 `lanternAt` 是画上的位置，`lantern` 是走起来以后的）。天上的光点只顺着丝带流；以前另有两串不在丝带上的——一串从驼队沿沙丘飘向城，一串从丝带下面贴着地平线滑向城——落在暗处像零星的流星，都已经去掉（`sky.ts` 里用 `gone` 记着去掉了几颗，好让星星留在原来的位置）。
- **什么时候不动**：没有脚本、开了「减少动态效果」、点了暂停、滚出首屏、标签页不在前台时，驼队和流光一起停（或一起不出现）；没出现时看到的就是原画，驼队在原位。暂停后再播放，从停下的地方接着走；暂停时改窗口大小，画布按停下那一刻重画一帧，不会退回原画。
- **避开字**：每次字体加载完、窗口大小变了、语言提示出现或关掉，`Page.astro` 都重新量一遍首屏上字和按钮的位置（换算成 canvas 上的位置，首屏缓慢推近的两头都算进去）。路要是从字底下过，新一队就改在字后面那段沙脊、从沙脊背后升上来；要是连画上原来那队站的地方都压着字，就不走、保持原画。丝带靠近字会整条淡下去。`.hero` 上的 `data-caravan` 写着这次是 `walks` 还是 `stays`。
- **手机竖屏和竖着的平板（`hero_tall.webp`）也走**（2026-11-27 加）：竖图上那队骆驼沿前景沙丘的脊线走，新来的队伍从画的左边外面走进来，走到沙丘顶翻到背面沉下去，过一会儿在远处那条亮路上冒出来（只剩灯火大小），顺着弯路进城；脚下一样有跟着走的光。和宽图不一样的地方：
  - **画是挂在字上的**。竖屏时字块从屏幕底往上排，多高要看语言和读者的字号（应用内置浏览器放大字号时，三个数字那几行会变高）；画要是照屏幕摆，第一行字在多数手机上正好压在沙脊上，驼队没地方走。所以竖屏（宽高比不超过 3:4，和换竖图是同一个条件）时画照字摆：`.hero` 的第二行网格正好是字块，`.scene` 放进这一行，从「字标和两行字之间那道空的正中」开始、到首屏底边为止；里面的画按「沙脊以下的部分正好填满这一块」定大小（`--ridge` 是沙脊那条线在画上的高度比例；这样盖不到首屏顶或两边时再放大）。于是不管什么手机、什么字号，沙脊都落在那道空的正中，驼队就在这道空里走，字标也总在画上同一个位置。首屏的暗色罩子竖屏时从 `.scene::after` 挪到 `.hero::after`，仍照屏幕铺。竖屏的推近以沙脊那条线为中心、不上下挪（`--drift-y` 为 0），驼队不会被推近带出那道空。那道空（`--gap`）手机上是 60–72px，竖着的平板是 88px 和屏宽 9.5% 里大的那个：要装得下骆驼、灯笼和脚下的光（合起来约为画高的十五分之一）。改字标的字号或行高，`.scene` 的 `top` 里那两个数（0.92、0.107）要跟着改；改完用各种手机宽度、中英文、放大字号各看一遍。
  - **仍然不压字**。`Page.astro` 每帧按推近当时的位置告诉驼队字在哪（`now`）；万一骆驼或光有哪一部分落进某一行字的范围（屏特别矮、字号特别大），那一部分不画，像从一堵矮墙后面走过，任何时候都不会画到字的上面或底下。画上那队要是有一半以上被字挡住，就不走、保持原画（`data-caravan` 为 `stays`；现在的排版下，320–430 宽的手机、竖着的平板、字号 100%–150% 都走）。远处的路从字标旁边过，驼队在碰到字标之前就淡成灯火。
  - **字按墨迹量**。竖图上一行字的范围按字的墨迹算（最高的字顶到最低的字底），不按整行的行框（行框上下各多出一截）；用字体自己的度量、再按这一行实际画出来的高度折算，所以浏览器把字放大了也量得准。宽图照旧按行框。
  - **队伍小一些**：普通一队 5 头、气派一队 8 头，气派一队不带丝带（沙脊短，上面就是字标，丝带往上飘会进字标）。骆驼身子用的还是宽图抠的那六格，放大 1.25 倍（竖图上画的骆驼大一些，`route.json` 的 `unit`）。
  - **路线逐点写了大小**（`route.json` 竖图每个点的第 4 个数）：近处的沙脊和远处的路之间隔得很远，大小不能像宽图那样按「离地平线多高」算。
  - 开页时跟在后面的头一队正好还在画外（`enter`），约 20 秒后从屏幕左边走进来；之后每隔约 44 秒来一队（普通的、气派的轮流），一队走完全程约 85 秒。画布的像素比最多按 2 算（`sky.ts`）。
  - 竖图的补丁 `patch_tall.webp` 抹掉的是那 5 头骆驼、牵骆驼的人和 6 盏挑灯，沙脊上那道橙色的光留着，灯雾减半；竖图没有前景遮挡图（翻过沙丘顶是「沉下去」，不是被一块图挡住）。
- **首屏推近**：`Page.astro` 里 `.drift` 的 `--drift-from`、`--drift-to`、`--drift-x`、`--drift-y` 和 `transform-origin` 是唯一的出处，`@keyframes drift` 和驼队都从这里读（驼队要在推近把它裁掉之前化成灯火）。改推近只改这几个数（竖屏另有一组：中心在沙脊线上、`--drift-y` 为 0，见上一条）。
- **素材**：图在 `public/hero/caravan/`（骆驼身子 `bodies.webp`、补丁 `patch_*.webp`、前面那块沙丘 `occ_*.webp`；宽屏用到的三张一共约 26 KB；竖屏用 `bodies.webp` 和 `patch_tall.webp` 两张，约 21 KB），数据在 `src/scripts/caravan/`（`route.json` 路线、`bodies.json` 每头骆驼的脚底、腿根、腿色、灯笼位置（走起来的和画上的）和贴图放大的倍数 `res`、`patch.json` 补丁位置）。
- **换了首屏的画以后**：补丁、路线和前面那块沙丘、骆驼身子都要照新画重做（路线上的点要照新画重标，灯笼位置是手量的，也要重量），再替换上面两个文件夹里的同名文件。生成这些素材的脚本不在本仓库里。

首屏以下第三段的演示视频在 `public/cover/`（中英各一条横版，约 0.7 MB，配一张封面图），是用代码做的，画面和出片脚本不在本仓库里；换视频只换 `public/cover/` 里的同名文件。

首屏的光和演示视频都有暂停按钮（WCAG 2.2.2），只在滚到眼前时才动；开了「减少动态效果」就不自动动，访客自己点「播放」才动。原来的丝带 [Ribbon.astro](src/components/Ribbon.astro) 现在没用上，留着备用。

## 在本地打开

准备 Git、Node.js（项目声明最低版本为 22.23.4）和 npm。首次接手时运行：

```bash
git clone https://github.com/bestduijin/bestduijin.github.io.git
cd bestduijin.github.io
npm ci
npm run dev
```

打开终端显示的地址，默认是 `http://localhost:4321/`。首页是英文版，直接访问 `/zh/` 可以检查中文版。要看语言提示，把浏览器的首选语言调成中文再打开 `/`；看过一次又关掉了的，在开发者工具里删掉 `localStorage` 的 `serico:lang-hint`。交付前按 Ctrl+C 停止开发服务，再预览实际要发布的版本：

```bash
npm run build
npm run preview
```

构建成功后，`dist/index.html` 和 `dist/zh/index.html` 分别对应英文和中文首页，`dist/en/index.html` 是 Astro 生成的跳转页（跳到 `/`）。

## 交付时怎么验收

在生产预览里逐项检查。键盘、页面语言和放大阅读的检查方法可参考 [W3C WAI Easy Checks](https://www.w3.org/WAI/test-evaluate/easy-checks/)。

- [ ] 直接打开和刷新两个语言地址都能读到完整内容。点击「中文」进入中文页，点击「English」回到英文页。打开旧地址 `/en/` 会到 `/`。
- [ ] 浏览器首选中文时打开 `/`，右上角语言链接下面出中文提示，不挡字标；点关闭后刷新不再出现。浏览器首选英文时打开 `/` 不出提示。
- [ ] 在手机宽度下读完开场自述和四个词源，文字没有被裁切。桌面浏览器放大到 200% 后，正文和链接仍可读、可用。
- [ ] 只用 Tab 和 Enter 就能切换语言、走到分工表的五个工序名并让视频跳过去，并能看清当前焦点。
- [ ] 演示视频播到哪道工序，分工表亮哪一行；点第 4 行，视频落在第 9 秒（第 4 道开头），原来在播就接着播、暂停就还停着。开「减少动态效果」刷新，表是普通的静态表。
- [ ] 首屏三个数字各点一次（也用 Tab 走到再回车），分别到「情形」「四步思路」「演示视频」，前两段大标题上面留着空、不贴顶，演示那段大标题和视频一起进屏幕。
- [ ] 页面和生成的 HTML 里搜不到 `bestduijin`、`foreign trade`、「科班」「读作」`Say it`、`trained programmer`。
- [ ] 切换系统深浅色，页面都是深色，正文与链接清晰可辨。首屏的字压在插画上仍然看得清；往下滚，丝线跟着画出来，不压任何字、视频和按钮，最后停在 serico；首屏和演示视频各点一次「暂停」都会停、按钮变「播放」。开启「减少动态效果」并刷新，两处都不自己动。
- [ ] 查看生成的 HTML，中文页的 `lang` 为 `zh-Hans`，英文页为 `en`；两页的描述使用各自语言，canonical 链接指向各自的正式地址，`x-default` 指向英文 `/`，`og:locale` 分别是 `en_US`、`zh_CN`。

## 发布到 GitHub Pages

仓库的发布流程监听 `main`。首次配置时，在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。改动合入 `main` 后，在 **Actions → Deploy to GitHub Pages** 查看构建与部署结果；成功后打开页首的两个正式地址复查。本站用自己的域名 `serico.ai`（在 Cloudflare 买的，DNS 也在 Cloudflare），在仓库 **Settings → Pages → Custom domain** 里填；用 GitHub Actions 发布时不需要 `CNAME` 文件。Astro 的 `site` 已配置为 `https://serico.ai`。DNS 怎么配见 [GitHub 官方：管理自定义域名](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)。[仓库发布流程](.github/workflows/deploy.yml) · [Astro 官方部署指南](https://docs.astro.build/en/guides/deploy/github/)
